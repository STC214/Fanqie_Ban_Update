## 已修复的主要问题

| 项目 | 修复与证据 |
|---|---|
| Android 8.0 资源兼容 | API 27 的导航栏属性移入 `values-v27`；基线 NewApi 错误消失 |
| Root 失败仍显示旧状态 | 失败时清空快照并禁用系统控制；完整性、类型、尺寸、密度和输出上限校验失败即停止 |
| 初始值持久化失败未阻止操作 | 原始值先原子同步到独立文件，再提交缓存；失败不启用系统操作，不覆盖已保存初始值 |
| 恢复脚本中断或假成功 | 原子生成脚本；设备端和 App 内恢复均读回 ADB、开发者选项、安装项和密度；读回不符时保留恢复材料 |
| DPI 确认与超时竞态 | 使用单次事务目录、独立脚本、原子改名争用决策标记；旧看门狗不复用新事务路径 |
| 恢复失败先删证据 | 原值恢复且读回成功后才清理日志；前台恢复失败时保留独立看门狗和重试记录 |
| 未结束预览重启后失去原值 | 持久化事务记录；重新打开 App 时恢复未确认状态，确认过的事务保持提交 |
| 锁屏计时与屏幕休眠 | 前台预览保持亮屏，后台按 `/proc/uptime` 检查超时；唤醒后不再额外等待完整 20 秒 |
| Activity 销毁后的回调和窗口 | 关闭受管对话框，移除计时回调，异步结果检查 Activity 生命周期，不更新旧窗口 |
| 读图阻塞 Root 操作 | 图片解码/保存与 Root 操作分队列，启动解码移出 UI 线程，损坏图片/OOM 回落默认底色 |
| 背景保存一半或取消后仍写入 | 新文件同步成功后提交设置；保存时锁定取消和编辑；失败保留文件并校验缓存恢复结果 |
| 背景删除后再次出现 | 使用明确的无背景标记，不依赖删除文件是否成功来决定下次加载 |
| Android 8 照片方向 | 补齐八种 EXIF 方向的等比变换；在真实 Android 图形实现中逐一核对尺寸及四角像素 |
| 旋转后取景预览失配 | 预览随主视口比例重算；横竖屏往返和保存后的比例检查通过 |
| USB 安装检测状态过期 | 写入前重新确认已识别设置项；不创建猜测键、不修改安装验证和未知来源策略 |
| 构建混入旧 class | 校验构建目录边界后清理生成目录；APK 中未包含审查组件、测试类或第三方运行时 |
| 备份迁移恢复错机参数 | 明确排除云备份/设备迁移的各存储域；原始系统参数留在本机 |

## 三条 Lint 建议与边界

保留原始警告，不通过静默降低严重性制造「零警告」：

1. **ExifInterface**：建议引入 AndroidX；本项目保持无第三方依赖，使用平台解码器和方向转换。八种变换已实际核对，但未在真实 API 26 设备遍历所有文件格式。
2. **OldTargetApi**：当前 target 为 API 36，与实测 Android 16 对齐；尚未以更高 target 发行，不声称覆盖未来行为变化。
3. **MonochromeLauncherIcon**：旧检查器检查基础 adaptive icon；实际 API 33+ 资源变体已有 monochrome 图标，APK 资源中存在，原图片图标保持不变。

其他边界：USB 安装仅支持已识别的独立键，本机已验证置灰，未对其他厂商的真实安装服务做放行/阻止试装；实际 Root 环境为本次 OnePlus/Android 16，未遍历所有 Magisk/APatch/KernelSU 版本；后台超时存在约一秒轮询/系统调度延迟，手机重启会结束 Root 看门狗，未确认事务在下次打开 App 时恢复。并发外部设置修改、全部第三方图片提供器和所有设备形态不作全覆盖承诺。

## 使用与回滚

手机已安装新版，可直接打开「轻控」。恢复系统值使用 App 中的按钮或本机 `restore-system.sh`；此次该脚本已真实执行并验证。

撤销本轮源码修复（不动手机，先校验当前文件，若被再次编辑则停止）：

```powershell
.\scripts\rollback-usb-control-audit.ps1 -VerifyOnly
.\scripts\rollback-usb-control-audit.ps1
```

旧发布包保留用于版本比对，不自动降级手机 App，也不以卸载清数据来冒充回滚。
